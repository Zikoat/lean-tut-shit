# Make the comparator check un-tamperable by the submitter

The untrusted AI authors the Submission PR, so it controls everything in that PR —
*including the workflow file as it runs.* For the `pull_request` event GitHub executes
the workflow definition from the PR's head/merge commit, not the base branch, so a
malicious PR can rewrite `verify-submission.yml` to skip comparator, fake a green
`verify`, and self-merge. The required `verify` status check is therefore **not** a
security boundary: it is spoofable both by rewriting the PR's workflow and by adding a
same-named job (branch protection matches required checks by context name only).

Two distinct threats, only one of which the sandbox addresses:

- **Threat 1 — untrusted code steals the write token or exfiltrates.** This is what
  landrun handles. landrun is Landlock-based, so it confines *filesystem and network* but
  not *environment variables*. The token is therefore unreachable provided (a) it is not
  placed in the comparator step's env, and (b) landrun's allowlist (driven by the
  *trusted* `config.json`, never the PR's) grants no read of token-bearing files nor
  network egress. Under that combined boundary, untrusted Lean elaboration — which
  executes arbitrary code (our `#eval` that writes a file proves it) — cannot reach the
  token. This is comparator's existing premise (ADR 0001), and we rely on it.
- **Threat 2 — the PR rewrites the workflow to skip comparator and self-merge.** landrun
  is irrelevant here; a rigged workflow simply never runs comparator. The only fix is to
  make the merge decision run from a workflow definition the submitter cannot edit.

## Decision

1. **Merge authority lives in a `pull_request_target` workflow.** Its definition (and, as
   of Dec 2025, its checkout) always come from the default branch, so the PR cannot tamper
   with it. It extracts **only** `Solution.lean` from the PR head; the lakefile, toolchain,
   `Challenge.lean`, and `config.json` come from the trusted base, so no PR-controlled file
   is ever executed outside landrun. It runs comparator (compile confined by landrun, token
   kept out of that step's env) and merges **only on its own real ACCEPT verdict** — never
   on "the `verify` check is green."
2. **The untrusted AI submits from a fork with zero write access.** This is load-bearing,
   not just a backstop: a same-repo PR could otherwise enable GitHub's native auto-merge
   itself and satisfy the spoofable `verify` name with a fake-green `pull_request` job — no
   privileged workflow required. Fork-only (no push, no auto-merge enablement) closes that.
   For the same reason, do not gate merging on native check-based auto-merge; merge from
   the trusted workflow's verdict.

We rejected the heavier alternative of a two-workflow split (unprivileged
`pull_request` produces a `lean4export` artifact; privileged `workflow_run` kernel-checks
it). That split's only gain over the above is defense-in-depth against a landrun *escape*,
since it runs the untrusted compile tokenless. Given ADR 0001 already trusts landrun, the
extra workflow, artifact plumbing, and export-format pinning are not worth it now. It
remains the natural hardening step **if** trust in landrun is ever weakened, because
comparator can kernel-check a pre-built export without re-running untrusted source.

## Consequences

- **Branch protection is defense-in-depth only.** Keep `verify` required, keep `strict`
  (closes the verify→merge TOCTOU), enable `enforce_admins`. Never rely on the `verify`
  name as the boundary — the token/privilege and fork boundaries are the real controls.
- `pull_request_target` footgun discipline is mandatory: extract only `Solution.lean`,
  keep the token out of the compile step's env, build only inside landrun, use trusted
  base-branch config for everything else.
- The current `pull_request` workflow's self-merge step must be removed; it grants a
  same-repo PR a write token inside a definition the PR controls (today's live break).
- Unchanged from ADR 0001: security rests on comparator/`lean4export`/kernel soundness,
  landrun, and an uncompromised `.lake`.
